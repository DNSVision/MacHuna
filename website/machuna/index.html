First launch

macOS will ask before it opens it

MacHuna is not signed with an Apple developer certificate yet, so the first time you open it macOS says it cannot verify the developer. That is expected. Three steps, once per machine.

  1. Move MacHuna to your Applications folder and double‑click it. macOS refuses to open it and shows a warning. Click Done.

  2. Open System Settings › Privacy & Security and scroll down. There is a line about MacHuna being blocked with an Open Anyway button. Click it and confirm.

  3. It opens, and opens normally from then on.

Verification status

What has been proven on a desk, and what hasn't

MacHuna is built by one person, with access to some desks and not others. Rather than let you find out the hard way, here is exactly where each output stands. Most of this is a statement about what has and has not been loaded onto real hardware, not about whether it works — with one exception, audio in EIF, which is genuinely not built.

OutputStatusWhat that means
Kahuna SWSclips, TGA sequences, stills Confirmed Verified on a live Kahuna mainframe. All seven standards checked byte‑for‑byte against reference files, along with fill and key, 16‑channel audio, the auto and loop play flags, and the >4 GB split. This is the path that has been in daily use.
Kayenne EIFnative Kayenne clips Untested on a desk The format was reverse‑engineered from real Kayenne clips and the header verified byte‑for‑byte. Converting between MOV, SWS, TGA and EIF is expected to work — it just has not been proven on a desk yet. Check the result before relying on it.
Audio in Kayenne EIFthe one known gap Not built yet EIF clips are silent. Kayenne keeps clip audio in a companion .eaf file. That format has now been worked out, but the code to read and write it is not written yet, so any audio on your source is dropped when converting to EIF — MacHuna tells you so in the log. This is the one thing on this page known not to work, rather than merely unproven, and it is next on the list. One question is still open: which of the eight audio channels a Kayenne treats as programme audio. If you know, or can find out on a desk, that is the last piece.
Kayenne TGA and MOV Untested on a desk Coded and routing correctly. Frame naming and format are taken from documentation rather than proven. Interlaced source to MOV is a known gap: ProRes carries no field‑order flag, and whether a Kayenne minds is unknown.
Sony MVS TGA Untested on a desk The four‑character clip naming is assumed from documentation. 25i field order defaults to TFF on an engineer's advice, with a toggle in the app if motion looks wrong on your desk.
720p1280×720 Not available Pulled in v1.6.8 because it was quietly producing corrupt files — the encoding maths is wrong for 1280‑wide output. Shipping something broken seemed worse than shipping nothing. I would like this one back: 720p/59.94 is still on air in the States, so it is a real gap rather than a dead format. It needs a reference file and a desk to check against.
SD, sF and 2160p Not available Not there yet, but not ruled out either. A standard only goes in the dropdown once it has been checked against a real reference file, because a wrong one produces files a desk will not read. If you need one of these, get in touch — with a reference file to work from, adding a standard is straightforward.
ConfirmedLoaded onto the real desk and verified. Use it.
Untested on a deskWritten to spec and believed correct, but never proven on the hardware it is for. It may work perfectly. Check the output before you trust it on air.
Not built yetKnown not to work. Not a bug — a feature that does not exist.
Not availableNot in this version. Ask if you need it.

One more caveat on a confirmed path. Progressive‑to‑interlaced conversion assumes top field first, which is standard for 1080i HD, but this has not been checked on a genuine 1080i Kahuna. If you have one and can look, that is a five‑minute job that would settle it.

If you have a Kayenne or a Sony MVS, testing one of the rows above and telling me what happened is the single most useful thing anyone could do for MacHuna. It is how the Kahuna row came to say Confirmed.

What changed

v1.8.1 9 Sep 2026 Current

Two fixes to the new item list.

The list now genuinely grows when you make the window taller — v1.8.0 claimed that and did not do it — and the scrollbar sits beside the list again rather than out at the edge of the window.

v1.8.0 9 Sep 2026

Batch numbering is now a list, so you can see what every file will be called before you convert it.

Each selected item gets a row showing its output name — alpha.mov → 42.SWS. Type a number per row, or tick Number sequentially and the first row fills in the rest. Converted rows lock with a tick and never run again, so you can add more files and convert without redoing anything. A ✕ removes a row, and the numbers below close up or stay put depending on how you are numbering.

Previously the numbering happened invisibly and you found out what each file had been called by reading the log afterwards. The Start number, Start slot and “Use source file number” controls are all gone, replaced by the list.

v1.7.1 8 Sep 2026

MacHuna now tells you, in the log, when an output has never been tested on the desk it is for.

Converting to Kayenne EIF, Kayenne TGA or MOV, or Sony MVS TGA writes a note saying so at the head of the batch. Kahuna SWS says nothing, because it is confirmed on real hardware and warning about it would be false caution. Converting a clip that has audio to EIF now also warns that the audio is dropped — see the verification table above for why. Nothing is blocked and no dialog appears; you are simply told where things stand.

v1.7.0 7 Sep 2026

A Help menu, with update notifications and a way to get in touch.

MacHuna now tells you when a newer version exists: a strip appears at the top of the window with what changed and a Download button. If you are up to date, offline, or the check fails for any reason, nothing appears at all — it is built for galleries and trucks with no route out. Help › Report a Problem and Suggest a Feature open an email with the version, your macOS and your current settings already filled in; nothing is sent until you send it. The user manual is now inside the app, so it opens with no internet.

The update check only ever reads one small file. It sends no information about you or your files, and there is no usage tracking.

v1.6.21 7 Sep 2026

A finished conversion now clears the selection, so the next one starts from nothing.

Previously the batch stayed loaded after converting, so reopening the folder browser offered Add to List and the files you had just converted came along and were written a second time. This now applies to every conversion, sequential or bespoke, and after a cancelled batch too. The auto‑incrementing start number is not reset.

v1.6.20 3 Sep 2026

The app reports its real version to macOS.

Every build used to report version 0.0.0 in Finder, so you could not tell one copy from another. Press ⌘I on the app to check which version you have. A copy still showing 0.0.0 is older than this release.

v1.6.19 3 Sep 2026

Clearer message when Sony TGA output is limited to one clip.

It now opens with how to convert a batch anyway, by ticking Use bespoke names, rather than leading with the restriction.

v1.6.17–18 3 Sep 2026

A blocked batch takes you to the field that needs fixing.

Every offending bespoke field is marked in red with the reason for that row, and the panel scrolls to the first one and focuses it. Correcting a duplicate clears the mark on its partner as well.

v1.6.13–16 3 Sep 2026

Bespoke per‑item output numbers and names.

Give each item in a batch its own output number, or its own four‑character clip name for Sony TGA, instead of taking an auto‑sequence. Blank, duplicate and already‑present values stop the batch and name the offenders, so nothing is ever overwritten. Batches can also be built from more than one folder.

Older releases are listed in the development notes that come with the app.

Problems and requests

MacHuna was vibecoded by one person against real desks, so it improves fastest when someone says what went wrong. There is nothing to sign up to.

machuna@dnsvision.tv
  • Something went wrong. Send the version, your standard, the source file and what the log said. MacHuna writes a conversion log into the destination folder after every batch, and that usually answers it.
  • It needs to do something else. A format, a standard, a naming convention your facility uses.
  • You have a Kayenne or a Sony MVS. Those output paths are written but have never been loaded on a live desk. If you can test one and report back, that is the most useful thing anyone could do for MacHuna.
